# 大軍の描画最適化

モデル形状・ポリゴン数・戦闘シミュレーションは変更せず、描画対象と更新量を減らす。

## 描画対象

- 96ワールド単位のセルを毎フレーム作り、実際の地面の高さとモデルの可動範囲で境界を計算する。死体も含む。
- セル判定のあとに兵士単位で判定する。旗、長槍、騎獣、攻撃・歩行・転倒の範囲を保守的な球で覆う。
- セルごとのメッシュは作らない。陣営・兵種・影の有無・部位ごとの `InstancedMesh` に対象の兵士を詰める。
- 影が画面内に届く可能性のある画面外の兵士も残す。太陽の方向へ境界を地表まで延ばして判定する。歩行可能な地表の下限は `ArmyView.shadowFloor`（標準0）。地形を負の高さへ変更する場合はこの下限も変更する。
- 全体が画面内に入り、影の対象距離外にあるセルは、兵士ごとの追加判定を省く。

表示対象の選別で `frustumCulled = false` を補っている。戦場全域に散らばる兵種バッチの境界球を更新しても個々の兵士は除外できないため、フラグを単に `true` にする方式ではない。

## 行列と転送

- 兵士オブジェクトをキーに基準姿勢と各部位の姿勢パラメータをキャッシュする。新しい戦闘でIDが再利用されても混ざらない。
- 各インスタンスの格納先に「姿勢オブジェクト＋部位の更新番号」を保存する。同じ姿勢が同じ場所にあるときは行列計算・書き込みを省く。
- 兵士の表示対象や順番が変われば、移動先の格納場所に現在の姿勢を書き直す。
- 動く兵士は計算結果を直接インスタンスバッファへ書き込む。部位ごとの行列を別の配列に二重保存しない。
- 旗も姿勢をキャッシュする。選択リングと矢は行列の値を比較する。変更範囲だけをGPU転送対象にし、未転送の範囲を次回更新で消さない。
- 地面の高さの取得と空間セルの更新は継続する。停止中でも地表・カメラ・選択状態の変更を取りこぼさない。

## 影

影あり・影なしのバッチを分ける。兵士と背負う旗は同じ分類を使う。影なしの兵士も地形や建物からの影は受ける。飛翔中の矢は従来どおり影あり。

現在の初期値（`armyVisibility.ts`）：

| 条件 | 影を有効にする | 有効な影を維持する |
|---|---:|---:|
| カメラからの距離 | 850以下 | 950以下 |
| 推定される兵の高さ | 6 CSS px以上 | 4 CSS px以上 |

距離と画面上の高さの両方を満たす場合だけ有効。境界付近の頻繁な切り替えを避けるため、有効化と無効化のしきい値を分ける。混在時は通常描画のバッチが増えるため、全景と接写の両方で評価する。

## 開発中の計測

開発サーバーのブラウザコンソールで実行する。

```js
window.__tlbRenderStats()
```

- `army.totalSoldiers` / `renderedSoldiers` / `culledSoldiers`：入力数・描画対象数・除外数。描画対象には画面外の影用兵士も含む。
- `army.shadowSoldiers`：影ありバッチに入った兵士数。
- `army.matrixCompositions`：基準姿勢・部位・旗の行列合成数。
- `army.matrixWrites`：書き込んだインスタンス行列数。リング・矢も含む。
- `army.dirtyMatrixBytes`：その更新で新たに汚れた範囲のバイト数。初回GPU確保や未転送範囲との結合を含まない目安。
- `army.updateMs`：可視判定を含む軍の描画データ更新のCPU時間。
- `simulationMs`：戦闘更新にかかったCPU時間。
- `renderSubmitMs`：`renderer.render()` のCPU側の処理時間。GPUの処理時間ではない。
- `frameCpuMs`：そのフレームのコールバックのCPU時間。フレーム間隔やFPSではない。
- `drawCalls` / `triangles`：Three.jsの描画統計（影パスを含む）。

再現用のCPUベンチマーク（Node 22.13以降、追加パッケージ不要）：

```sh
node scripts/benchmark-army.mjs
# 指定したローカルGitリビジョンの army.ts と比較する場合
node scripts/benchmark-army.mjs --baseline=HEAD
```

5,000体・10,000体、全景移動・接写移動・全景一時停止を計測する。モデル・補助モジュールは現在のものを使い、ベースライン指定時には `army.ts` だけを過去版に差し替える。WebGL・実地形・戦闘計算は含まないため、ゲームのFPSと混同しない。

## 手動確認の観点

全景・接写・旋回・画面端での移動を比較し、長槍と旗の欠け、画面外から入る影、地形上や橋上の兵士、転倒と沈む死体を確認する。一時停止中はカメラ移動・部隊選択・選択解除を試す。移動再開や新規戦闘で古い姿勢が残らないことも確認する。

## 実装中の確認記録

最終の行列コピー削減・旗キャッシュ調整より前に、追加テスト11件と本番ビルドは成功。全体テストは145件成功、`app/game/battle.spec.ts` の以下3件が失敗した。戦闘ロジックはこの変更では編集していないが、変更前の版での再現確認はしていない。

- 突撃後の戦死者数：期待100超に対して61。
- 拠点で補給後の命令：期待 `move` に対して `resupply`。
- 工兵と歩兵の解体速度比：期待3.6未満に対して約4.13。

ユーザーが確認テストを担当する方針になったため、最終調整後のテスト・ビルド・ベンチマークは実行していない。特に全景移動時は、可視判定とキャッシュ管理のCPU負荷を影描画削減の効果と合わせて確認する必要がある。
